# Hat Trick (sports scores app)

Free, open-source Android app (Expo / React Native): NHL scores, standings, leaders and box scores first, more leagues later. Package `io.github.peakears.hattrick`, repo `peakears/hat-trick`. Not on app stores: users install the APK attached to each GitHub Release, or build it. Everything runs on the device, no backend. Data comes from public APIs. Versions and dates: GitHub Releases and CHANGELOG.md. What the app does: README.

## Architecture (data flows up)

adapters -> domain model -> on-device cache -> Expo app UI

- `src/domain.ts`: league-agnostic types and the `LeagueAdapter` contract. Nothing here knows raw API shapes. `src/registry.ts`: `AdapterRegistry`, adapter by league id.
- `src/adapters/nhl/`: `client.ts` (HTTP), `errors.ts`, `constants.ts`; `raw-types.ts` (zod schemas, types inferred) and `validate.ts` (policy); `mappers.ts` (raw -> domain); `adapter.ts` (fetch -> validate -> map); `__fixtures__/` (recorded responses). Which endpoint has what, and what is still unverified: `src/adapters/nhl/CLAUDE.md`.
- `src/contract/league-adapter.contract.ts`: suite every `LeagueAdapter` must pass; a new league's test calls `runLeagueAdapterContract()` with fixture-backed adapters.
- `src/data/`: the only thing the UI calls. `sports-data.ts` (`SportsData`: cache-first reads returning `Fetched<T>` = `{ data, meta }`, offline fallback to last known data, shared in-flight requests, `prune()`), `freshness.ts` (all TTLs), `store.ts`, `types.ts`.
- `src/ui/`: code shared by screens. Files called pure have no React Native imports and are tested in `ui.test.ts` or their own test file; screen logic goes in a pure file so it can be tested.
  - `sports-data-context.tsx` creates the one `SportsData` (NHL adapter + `AsyncStorageStore`) and prunes on start; `LEAGUE` is the shown league.
  - `use-polled.ts` `usePolled(key, load)`: loads through `SportsData`, re-polls at `meta.staleAt` (`polling.ts`, pure), and only polls the screen shown: it pauses in the background and when its screen loses focus (tabs and stacked screens stay mounted), and checks again, cache-first, on return. `refresh()` is ignored while the data on screen is under 30 s old (`canManualRefresh()`), except when nothing loaded or the data is an offline fallback.
  - Pure helpers per screen: `format.ts` (Scores order and sections, records, venue, date picker dates at local noon so DST cannot shift the day), `goals.ts`, `standings.ts`, `leaders.ts`, `team.ts`, `player.ts`, `special-events.ts`, `stars.ts`, `broadcasts.ts`, `spoilers.ts`, `swipe.ts`.
  - Scores: a swipe or arrow changes the day, and the day you stop on loads 250 ms later (`use-swipe.ts`, `use-debounced.ts`), so quick swiping makes no request per day passed. "Today" rolls over at 5am local (`use-today.ts`), so late games stay under Today.
  - Spoiler shield (`spoilers.ts`, `spoiler-context.tsx`): it only changes what is drawn; data is still fetched and cached. Reveals are in memory only. Standings and Leaders are deliberately not shielded.
  - Settings (`settings.ts`, pure, with `settings-context.tsx`, stored under `settings:v1`): a new preference needs a default and a `.catch()` schema field, no version bump.
  - Device-only code is kept in one file each, behind pure logic: `reminders-native.ts` (the only `expo-notifications` code; plans come from `reminders.ts`), `updates-native.ts` (the only file-system and installer code; the flow is `install-update.ts`, with device steps passed in as ports). TV region: `use-tv-region.ts` (setting, or the phone's region via `expo-localization`).
  - `components/`: `StatGrid` is the generic stats table (`StatTableView` wraps it for player tables); `TeamLogo` (expo-image, NHL logos are SVG) and `PlayerHeadshot` fall back to an abbreviation or initials and follow the `showLogos` setting.
- `app/`: Expo Router. `(tabs)/`: Scores (`index`), Standings, Leaders, Settings. `game/[id]/index` (game page) and `game/[id]/box-score`, `team/[id]`, `player/[id]`, `spotlight` (opened from Leaders). Open games with `pathname: "/game/[id]"`. The root layout wraps the app in `SettingsProvider` and `SportsDataProvider`; it and the game, team and player pages export an `ErrorBoundary` (`CrashScreen`).
- `app.json` is static Expo config; `app.config.ts` adds `version` and `versionCode` from `package.json`, so never put a version in `app.json`. `android/` is generated by `expo prebuild`, not committed.

## Patterns

- **The field you want may not be in the response you expect.** Goals are not in the box score, special events are not in `/score`, club stats have no team name. Check `src/adapters/nhl/CLAUDE.md` before assuming a field exists, and record a fixture when it does not say.
- **Extras are best effort.** A screen's main request decides whether it loads; anything added from another request (the game page's goals, three stars and special event, the team page's schedule) is caught in the adapter and left out if it fails. A new extra follows the same pattern, and a test drops it to prove the screen still works.
- **One `usePolled` per source that can fail on its own.** The team page loads `standings` and `team:{id}` separately, and Scores loads the scores and the week's special events separately, so one failure never hides the other's data.
- **Share cache entries instead of fetching again.** The team page and the game page read the Standings tab's `standings` entry; the game page and box score share `game:{id}`; Scores and the game page share `events:{monday}`. Use the same key and the data costs no request.
- **Keep slow-changing data out of fast polls.** A live game re-polls every 20 s; data that never changes during a game (special events) gets its own key with a long TTL rather than riding along with the poll.

## Rules

- Only an adapter may touch raw API shapes. Everything above it uses domain types. Team ids are three-letter abbreviations.
- Validation: core fields (ids, teams, scores, game state, standings W/L) use plain zod and throw `NhlResponseError`. Minor fields use `minor()` and are dropped with an `onWarning` call. Lists (box score rows, goals, broadcasts) use `lenientArray()`: one bad item is dropped, not the whole response.
- The NHL API (api-web.nhle.com) is unofficial and unreachable from Claude sessions. Anything new needs a recorded fixture first (see Recording a fixture).
- All code outside tests must run in React Native (Hermes): no Node-only or browser-only APIs (e.g. no `AbortSignal.timeout`). Tests use `tsconfig.test.json` (Node types).
- The UI never calls adapters; screens call `SportsData` through `usePolled`. TTLs live in `freshness.ts`.
- Cached entries live under `cache:` keys with a `CACHE_VERSION`. Bump it whenever the shape of a domain type changes, or old cached data is read as the new shape.
- Tests never hit the live API: use recorded fixtures, and simulate drift by editing a fixture in the test.
- API keys (future leagues) are entered by the user and stored with `expo-secure-store`; never commit keys. Keyless leagues like NHL must work with no setup.
- Network calls: the NHL API and GitHub. Update checks use `api.github.com/repos/peakears/hat-trick/releases/latest` (daily at most; switch in Settings). An APK is downloaded only when the user taps Update, only from this repo's release links (`isReleaseApkUrl`, `isReleasePageUrl`: they match the whole URL, not a prefix, so `..` cannot leave the repo; stored links are checked again on read), into the cache folder (never Downloads), then Android's installer opens; the file is deleted after a failed or cancelled install and on next launch. Keep the README's privacy line true.
- Never commit league logos, player photos or other trademarked assets (their URLs come from the API at runtime). The app icon is original artwork generated by `scripts/icons/generate.py` (rendered by `render.cjs`): change the script, not the PNGs.

## Recording a fixture

Claude cannot reach the NHL API, so the user records responses locally. Give them the exact commands, for example:

```sh
cd src/adapters/nhl/__fixtures__
curl -s https://api-web.nhle.com/v1/schedule/2026-11-17 -o schedule-2026-11-17.json
```

- Name the file after the endpoint: `score-<date>`, `schedule-<date>`, `boxscore-<gameId>-<state>`, `landing-<gameId>-<state>` (state: `final`, `live`), `player-<id>-landing`, `club-stats-<team>-now`, `standings-now`.
- To learn where a field lives, record the same game from more than one endpoint and compare.
- Then: add the file to `FIXTURES` in `nhl.test.ts` with its recording date, write the schema in `raw-types.ts` with a "Verified on <date>" comment, update `src/adapters/nhl/CLAUDE.md`, and commit the fixture with the feature that uses it.

## On-device constraints

- Live updates come from polling while the app is open (cache TTL). No server, so no reliable push while closed; local notifications are fine (puck drop reminders use `expo-notifications` date triggers; Android may delay them a few minutes). `expo-notifications` bundles Firebase Messaging, which matters for F-Droid/IzzyOnDroid (#27).
- Android/iOS only: the NHL API probably blocks browser (CORS) requests, so an Expo web build would need a proxy.

## Commits and releases

- Conventional Commits (`type(scope): subject`, scope optional), checked by a husky hook (commitlint) and in CI. `feat` is a minor bump, `fix` a patch; `feat!:` or a `BREAKING CHANGE:` footer is major, avoid unless there is a real reason. `docs`, `test`, `refactor`, `perf`, `build`, `ci`, `chore`, `style` cause no release (`perf` is in the changelog).
- release-please (`.github/workflows/release-please.yml`) keeps a release PR open with the next version and CHANGELOG. Merging it creates a draft GitHub Release; the workflow builds the APK, attaches it, then publishes the release (which creates the tag). Never edit the version in `package.json` or `.release-please-manifest.json` by hand.
- APKs: `.github/workflows/android-apk.yml` (`expo prebuild` + Gradle, JDK 17). Releases are signed from the `ANDROID_KEYSTORE_*` / `ANDROID_KEY_*` secrets (never commit a keystore). PRs get a debug-key test APK (artifact, `arm64-v8a` only); it is not a required check.
- **Before merging a release PR**, check the docs are current (README features and Settings line, the roadmap here) and the release PR's version and changelog. If something is stale, fix it in a `docs/...` PR and merge that first: merging the release PR publishes immediately.
- Workflow: one branch per feature from `main` (`feat/...`, `fix/...`, `docs/...`), one PR each, squash-merged (the PR title becomes the commit, so it must be a Conventional Commit). PR bodies have a summary and a Testing checklist (typecheck, tests, bundle, on a device); tick "on a device" only once the user has seen it. Feature PRs update the README.
- **Before pushing a new branch, check the name is free**: `git ls-remote --heads origin <branch>`. Another Claude session (cloud, or another device) may already have pushed one. If it exists, look at it and ask before overwriting; never force-push over a branch you did not create.
- Open PRs often conflict in `src/ui/format.ts`, the `ui.test.ts` imports and the docs: merge one, rebase the next onto `main`, keep both sides, run typecheck and tests, push with `--force-with-lease=<branch>:<old sha>`. Two PRs that bump `CACHE_VERSION` to the same number merge with no conflict: the second must bump it again.

## Commands

- `npm install`, `npm run typecheck` (app + tests), `npm test` (vitest), `npm run format` (Prettier, `printWidth` 120; CI runs `format:check`, so run it before committing).
- `npm start` (Expo Go), `npm run android` (native build, needs the Android SDK). Expo Go keeps the old bundle after a dev server restart: press `r` (or shake the phone, Reload) after switching branches.
- `CI=1 npx expo export --platform android --output-dir <tmp dir>` checks that Metro can bundle the app without a device.
- Add Expo packages with `npx expo install <pkg>` (matches the SDK). If api.expo.dev is unreachable, take the version from `node_modules/expo/bundledNativeModules.json` and `npm install` it. `react-dom` is pinned to the same version as `react`.
- `npm audit` advisories are build tooling only. Do not run `npm audit fix --force` (it downgrades vitest and breaks Expo).
